# AI 模块联调 / AI 모듈 연동

这份说明只覆盖杜君负责的 AI 服务和复盘网页。行情主页、用户账户、交易保存、学习与积分仍由对应成员负责。

美股日 K 自动背景与书籍参考已接入，范围与边界见 [书籍与行情背景方案](book-based-market-context-plan.md)。用户无需手写 K 线摘要；其他市场暂可留空。

이 문서는 두군의 AI 서비스와 거래 복기 화면 연동을 설명합니다. 실시간 시세 홈, 계정, 거래 저장, 학습 및 포인트는 각 담당 모듈에서 구현합니다.

## 本地运行

AI 服务使用 Python 3.11 或 3.12。安装方法见 [AI Service](../ai-service/README.md)。在 `ai-service` 目录启动：

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8001
```

另外打开一个终端，在仓库根目录启动网页：

```powershell
python -m http.server 5173 --bind 127.0.0.1 --directory web-demo
```

- 网页：`http://127.0.0.1:5173/`
- 接口文档：`http://127.0.0.1:8001/docs`
- 机器可读契约：`http://127.0.0.1:8001/openapi.json`
- 默认 `USE_MOCK_LLM=true`，不需要密钥。健康检查返回 `analysis_mode: mock`。
- `localhost` 只指访问者自己的电脑。此配置只用于本机演示，尚不是公网部署或多人服务。

## 一条命令检查接口

在 `ai-service` 目录运行：

```powershell
.\.venv\Scripts\python.exe scripts\smoke_test.py
```

它会检查健康状态、中韩文合成行情及书籍笔记、单笔分析、7/30/90 天画像以及截图上传。只允许 Mock 服务；遇到 LLM 模式会在发送分析请求前停止，避免意外调用付费模型。测试不请求真实 Yahoo 行情。

不启动服务器也可以检查应用内部接口（不验证监听端口或浏览器连接）：

```powershell
.\.venv\Scripts\python.exe scripts\smoke_test.py --in-process
```

中文和韩语样例位于 `ai-service/examples/trade.zh-CN.json`、`trade.ko-KR.json`。全部是虚构演示数据，不是历史行情或真实交易。HTTP 请求的 JSON 应使用 UTF-8。

## 调用顺序

1. 可先用股票代码、带时区的买入时间调用 `POST /analyze-market-context`，把 `kline_summary` 和 `rag_context` 放入交易请求对应字段，再调用 `POST /analyze-trade`。详见 [API 契约](api-contract.md)。行情不需要模型密钥，书籍展示默认是主题规则匹配。
2. 保存完整响应，按 `trade_id` 更新，不要把同一笔交易的重试当作新增样本。
3. 把同一用户的分析响应数组放入 `trade_analyses`，调用 `POST /analyze-profile`。
4. 时间窗默认以最新一笔交易为基准；需要以指定日期统计时传 `as_of`。建议所有交易时间使用带时区的 ISO 8601。

仅买入但尚未卖出的交易，`sell_time` 和 `sell_price` 必须同时为空；未知盈亏保持 `null`。不要把空白卖出价填成零。`profit_loss_rate` 使用小数，例如亏损 2% 为 `-0.02`。

语言代码统一使用 `zh-CN` 或 `ko-KR`：单笔请求放在 `analysis_context.language`，画像请求放在 `language`，图片表单放在 `language`。其他代码返回 422。技术标识如 `FOMO_BUYING` 保持不变，界面文案使用本地化名称。

## 截图到分析

`POST /recognize-trade-screenshot` 接收 multipart 表单：`file` 和 `language`。PNG、JPEG、WebP，最大 8 MiB。返回的字段必须先供用户核对，再构造单笔分析请求。

| status | 调用方处理 |
| --- | --- |
| `mock` | 没有执行视觉识别；显示提示，不要把字段当成识别结果 |
| `needs_review` | 没有可靠交易字段；保留用户原有表单，提示重新上传或手动输入 |
| `recognized` | 有部分可见字段，不代表信息完整或已确认；在逐字段核对表中确认后才替换表单，补充理由后再分析 |

缺失字段为 `null`，空白字符串也会规范化为 `null`。置信度只对应有值的字段，且是模型自评，不代表识别准确率。网页把识别结果暂存供用户核对，只有显式确认才替换交易表单；未确认、正在识别或更换文件时不能开始分析。日期缺少年份或无法解析会丢弃。即使日期可解析，截图时间缺少交易时刻或时区时也不会自动换算成本地午夜，需用户自行补齐。多行交易没有明确选中行时，提示用户裁剪到一笔明确交易；当前版本不支持批量自动入库。

## 错误处理

| HTTP 状态 | 意义 | 界面处理 |
| --- | --- | --- |
| 404 | 行情不存在或未取到 | 核对代码、日期；不要当成零价格 |
| 413 | 图片超过上限 | 提示换小图 |
| 415 | 图片类型或签名不支持 | 提示 PNG/JPEG/WebP |
| 422 | 请求字段或语言不合法 | 提示检查表单；`detail` 可能是字段错误列表 |
| 503 | LLM 模式未配置密钥 | 显示服务未配置，不要伪造结果 |
| 502 | 模型调用失败、超时或返回内容不合法 | 保留表单，让用户重试或手动输入 |

真实模型调用失败不会自动返回 Mock 结果。开启自动行情时，获取失败会停止提交；用户可重试或关闭自动获取。关闭后网页在无法连接服务时有明确标注的本地规则演示；它不是线上模型服务。

## 演示前检查

- 全部单测、联调脚本通过，网页显示 `服务已连接 · Mock` 或对应的韩语状态。
- 用中韩文各分析一笔虚构交易，再查看行为画像。
- Mock 模式上传截图应明确提示未执行 OCR，不能作为真实截图识别的验收。
- 真实模型与 OCR 需要另行配置密钥、确认服务可访问并做真实验收；当前离线测试不能证明模型实际识别准确率。
- 关闭终端或重启电脑后需要重新启动服务。老师从自己的电脑访问前，需要另做正式部署与访问控制。
