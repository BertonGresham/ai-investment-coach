# 团队任务

## 当前共同目标

首版为中韩文网页，不要求同时交付手机 App。统一从 `dev` 开始，操作见 [组员开始指南](team-start.md)。以下是下一步交付目标，不代表各成员已经完成。

先跑通：首页 -> 模拟交易 -> 主后端保存 -> AI 复盘 -> 保存报告 -> 历史查询。随后接入最小学习、测验、积分和一种券商 CSV。VIP、实物商城、新闻系统和手机上架后置。

## 杜君：AI分析模块

负责目录：

```text
ai-service/
web-demo/ 与AI结果页面相关部分
docs/api-contract.md 中AI接口部分
```

当前任务：

- 维护已有 Claude、截图识别、多笔成交和中韩文复盘能力，固定输入输出契约
- 使用确认可用且有来源的书籍笔记完成实际向量检索；当前主题规则匹配不等于完整 RAG
- 与业务后端对接历史报告和画像；当前统计为 7/30/90 天，如需改变应同步接口和介绍书
- 将复盘子页面接入金佳亮的总首页；不重复承担全部业务模块
- 管理GitHub仓库结构和接口文档

验收标准：

- AI服务可以本地启动
- Swagger页面可访问
- 队友保存的交易能生成复盘，报告展示成交事实、来源、建议和不确定性，并能从历史页面重新打开

## 金佳亮：模拟交易系统

负责目录：

```text
网页总首页、行情和模拟交易界面（接入现有web-demo，先协调路由和共享文件）
backend-server/ 与交易相关接口配合
```

第一阶段任务：

- 负责中韩文网页总首页、导航、股票列表和基础 K 线；复用 AI 复盘子页面
- 实现模拟买卖、持仓、成交列表和理由选择；提交每次成交的明细
- 与 Young 对接交易保存和持仓校验，与数据服务协调行情格式
- 行情标注来源、时间和延迟；历史或合成数据不能标为实时数据
- 保留现有 Expo 原型供后续复用，不要求同时维护完整手机 App

验收标准：

- 前端可以启动
- 用户能看到学习、积分、模拟交易、AI分析四个核心入口
- 用户能完成一次模拟买卖，保存后打开对应 AI 报告；暂缺接口用明确标注的模拟数据联调

## Young：后端主业务

负责目录：

```text
backend-server/
docker/docker-compose.yml 中MySQL和Redis部分
docs/database-design.md
```

第一阶段任务：

- 启动已有 Spring Boot 基础项目并连接 MySQL
- 优先实现最小用户身份、逐笔交易保存/列表/详情和 AI 报告保存/查询
- 交易记录支持分批买卖；服务端校验持仓、资金和用户归属，不信任前端 user_id 或盈亏
- 对接 AI 服务并按 trade_id 防止重试重复入库；模型密钥不放前端
- 再完成课程、测验、积分流水、防重复领取和模拟交易解锁，协调积分扣除规则
- 商城后置，先完成交易到报告的持久化闭环

验收标准：

- 后端可以本地启动
- `GET /api/health`返回正常
- 刷新或重新进入后仍能查询本人交易和报告；不同用户记录隔离，重复领取积分被阻止

## Joo Jiho：数据管道

负责目录：

```text
data-service/
docs/api-contract.md 中数据接口部分
```

第一阶段任务：

- 先支持一种券商 CSV，规范股票、市场、币种、买卖方向、时间、价格和数量
- 对接 AI 的逐笔 executions 格式，处理重复和缺失字段，排除利息/入出金等资金流水
- 复用并协调已有美股历史日 K 适配器，向首页和复盘提供明确来源、截止日期的数据
- 不重复建设一套券商成交截图 OCR；已有能力在 AI 服务中，数据质量边界与杜君共同确认
- 单纯 K 线图不等于用户成交记录；不能由图表猜买卖时间、数量或理由。公告和新闻后置

验收标准：

- 数据服务可以本地启动
- Swagger页面可访问
- 样例 CSV 转为 AI 可用的逐笔记录并保留分批买卖；缺失信息不编造，历史背景不混入交易后的数据
