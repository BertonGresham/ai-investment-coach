# 自动行情背景与书籍解释：MVP 范围

状态：设计与分工约定，不是已完成的功能。当前网页的 K 线摘要是可选手动输入；后端可以在没有行情摘要时分析用户明确填写的交易理由。截图接口目前提取交易记录字段，不等于 K 线图技术分析。

## 用户最终需要做什么

1. 选择模拟交易或上传交易记录，确认股票、市场、交易时间和数量。
2. 填写自己的买卖理由、事前计划；系统不能从盈亏或 K 线猜测这些内容。
3. 系统自动展示交易当时的行情事实、有关书籍观点及本次行为复盘。

用户不必手写 K 线分析。人工补充仅保留为可选信息，且应与系统获取的数据分别标记来源。

## 三类输出分开

| 层次 | 数据来源 | 示例含义 |
| --- | --- | --- |
| 可核对的行情事实 | 历史 OHLCV 与指标计算 | 某一时间段内的涨跌幅、成交量相对变化；必须附时间范围 |
| 书籍概念解释 | 有来源的知识卡检索 | 哪个概念可以帮助理解当前现象，依据是哪本书的哪一节，以及适用限制 |
| 用户行为复盘 | 用户理由、事前计划与当时行情 | 是否出现错失焦虑的线索、是否按计划行动；不能只因亏损就认定行为错误 |

书籍观点不是股价预测器。检索到“追涨”相关概念也不代表用户一定在追涨，必须回到用户提供的理由与证据。

## 数据流与分工

```text
交易代码 + 市场 + 买入时间
    -> Joo Jiho：恢复当时可获得的历史行情
    -> 数据服务：计算有限的量价特征并生成事实摘要
    -> Young：保存来源信息，把摘要与交易交给 AI 服务
    -> 杜君：检索相关书籍知识卡，生成带引用与局限说明的解释
    -> 金佳亮的行情主页 / 杜君的复盘页：展示与用户核对
```

不要等队友完成整套功能再联调。先约定一份固定的虚构行情输入，通过样例把数据服务与 AI 的字段对齐，再替换为真实数据。

现有 `/analyze-trade` 可直接接收 `market_snapshot.trend_before_buy`、`volume_price_summary`、`kline_summary`、`news_summary`。自动行情适配器尚未实现；这些字符串目前不会自动抓取数据。未来的原始 OHLCV、指标及来源元数据契约需要单独版本化，不能把任意额外字段直接加入当前严格校验的请求。

## 一个月内建议范围

- 只接一个股票市场和一个行情来源，先做历史日 K 的复盘，不做实时分钟级全市场分析。
- 先计算少量可核验特征，例如区间涨跌幅、成交量与之前均量之比、价格相对移动均线的位置；缺数据时明确为空。
- 先选 1–2 本已确定且可使用的书，整理约 20–30 张有标题、来源、章节/页码、适用条件和局限的知识卡。保留版本或版次，避免页码无法核对。
- 首轮覆盖几种典型案例以及“信息不足”案例，不声称全面识别所有形态。
- 网页支持中文、韩文解释；原始书名与引用位置应保持可核对，不能伪造译本页码。
- 暂不做全部券商、批量多交易截图、专业行情终端、自动买卖建议或收益预测。

工作量估计：假设数据来源可访问、书籍材料已确定、成员并行推进，这个受限版本约需 1–2 周开发与联调。数据授权、接口不可用、分钟级历史数据缺失或识别准确率不足会增加时间；这不是交付承诺。

## 避免事后信息误导

- 评估买入决定，只使用买入时已经可获得的数据；卖出后的走势不能倒灌为买入依据。
- 若使用日 K，而买入发生在盘中，当天完整日 K 在那个时点尚不存在。第一版可使用前一完整交易日及更早的数据，并清楚标注时间范围。
- 交易日、时区、停牌、复权方式与量价单位由数据模块明确处理。
- 财经新闻或公告若尚未接入，保留缺失状态，不用模型“补全”历史事件。

## 当前已经有与仍缺的内容

已有：交易分析接口、中韩文输出、RAG 检索和引用校验的基础代码、行情摘要输入字段、离线模型调用测试。

当前知识文件只有四张团队原创行为知识卡，不是已经导入的经典书籍。向量建库仍需配置 Embeddings API，真实模型调用和识别准确率也尚未验收。

仍缺：真实书籍知识卡、自动历史行情接入、量价特征计算、书籍解释的专项输出与真实案例评估。不能把当前 Mock 结果当成“已经按经典书籍分析了真实 K 线”。

## 验收标准

- 用户不填 K 线摘要时，成功接入行情模块后也能获得带数据时间范围的行情背景。
- 找不到行情或相关知识卡时明确说明缺失，不编造数据或引用。
- 每条书籍解释可追溯到实际检索到的知识卡。
- 中韩文输出区分事实、理论解释与行为推断，并说明样本和证据限制。
- 使用事先准备的人工核对样例检查数据正确性、引用准确性和语言质量；单元测试通过不能替代真实模型验收。
